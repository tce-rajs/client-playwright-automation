Test design

Over half the suite is built to break things

Positive checks confirm a feature works. Negative, boundary, and security cases are where nearly every real bug in this report was actually found.

Findings

18+ real, reproducible bugs

Each one was confirmed live — screenshot or DOM evidence, reproduced more than once — not inferred from a single failed assertion.

Critical

Attendance panel hangs on its own loading spinner, forever

Never renders the roster. No way to exit from inside the panel. Reproduced across multiple subjects.

Critical

Four distinct actions crash the page outright

Bold on a selected text object; rapid class-switching (6+ classes); a malicious string in the curriculum response during login; a Checkpoint's End button.

High

Whiteboard content is lost on reload / class switch

Confirmed real data loss — gives the earlier "Save button does nothing" finding an actual damaging consequence.

High

Whiteboard History leaks across classes

Scoped per-teacher-account, not per-class — a security/data-scoping gap, not just a display bug.

High

Two systemic bug families, each confirmed in 3+ unrelated modules

Toolbar/FAB-launched panels don't close on class switch (Attendance, Drop It, Minimap). Compose dialogs block the class switch entirely (AI Notices, AI Homework).

found via adversarial pass
Medium

Change Password and Change PIN can both be open at once

Source-level logic bug: the guard condition uses AND where it should use OR.

Medium

Auto-Generate PIN shows the new PIN in plaintext on screen

A shoulder-surfing risk in a live classroom setting.

Adversarial pass

A dedicated round built to break the app

On top of the baseline suite: extreme inputs, rapid/repeated clicks, mid-action interruptions, and cross-account checks — every module, purpose-built to find what normal usage wouldn't.

The plan

What's left

1

Finish routing every module through the shared class map

23 of 91 spec files now pull their Class/Chapter/Topic setup from one confirmed-working map instead of a hardcoded literal. The rest still work fine — this closes the last gap for maintainability.

In progress
2

Run the suite against the real desktop client

A Playwright fixture already knows how to launch the Electron app and find its embedded webview. No test file uses it yet — this is the next real milestone.

Fixture ready
3

Consolidate each module down to one spec file

Three build passes (original, gap-analysis, adversarial) left most modules with 2–4 separate files. No coverage is duplicated, but a single clean file per module would be easier to navigate.

Not started
4

Escalate the two systemic bug families and the data-loss finding

Panels not closing on class switch, composers blocking class switch entirely, and confirmed Whiteboard data loss on reload — all reproducible, all worth a developer's attention first.
